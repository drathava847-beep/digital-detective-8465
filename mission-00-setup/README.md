## 4. My understanding

A repository holds project files and uses Git to record their changes.
GitHub hosts the repository online.

Cloning created a local copy on my Mac and connected it to the GitHub
repository. I did not need to fork my own repository or run git init
after cloning.

The mission folders keep each activity organised. README.md documents
explain the work using Markdown. The main README introduces the project,
while each mission README records that mission’s work and learning.

Creating a file locally does not automatically publish it on GitHub.
The changes must be committed and pushed.

## 5. Difficulties faced

I was initially unsure about the difference between forking, cloning,
and initialising a repository.

The command touch README.md mission-*/README.md produced the error:
zsh: no matches found: mission-*/README.md

I also needed help understanding README formatting and relative links.

## 6. How I resolved them

I learned what each Git operation does and used cloning for my existing
GitHub repository.

I learned that zsh tries to match wildcard paths before running the
command. The README files did not exist yet, so the wildcard did not
match them. I created the files using their individual paths.

I practised Markdown headings and links. A relative link points to
another document using its location within the project.
